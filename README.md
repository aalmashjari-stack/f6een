# فطين

لعبة أسئلة عربية جماعية تُلعب على شاشة واحدة كبيرة، يشغّلها شخص واحد كحكم.

مصدر الحقيقة لقواعد اللعبة والشاشات: [`docs/SPEC.md`](docs/SPEC.md).

## التشغيل

```bash
npm install
cp .env.example .env   # ثمّ املأ مفاتيح Supabase (ومعرّفَي غوغل للتطبيق الأصليّ)
npm run dev
```

يفتح على `http://localhost:4173` — المنفذ ثابت عمداً (`strictPort`): الذاكرة
المحلّية مربوطة بالأصل، ولو تبدّل المنفذ ضاع سجلّ الأسئلة المستخدمة.

### الفتح على التابلت

خادم التطوير يستمع على الشبكة المحلية. عند التشغيل يطبع سطرين:

```
Local:   http://localhost:4173/
Network: http://192.168.x.x:4173/
```

افتح عنوان `Network` في متصفّح التابلت — بشرط أن يكون على نفس شبكة الواي فاي.
أضِف الصفحة إلى الشاشة الرئيسية لتعمل بملء الشاشة بلا شريط عناوين.

### النسخة المنشورة

```bash
npm run build && npm start
```

`server.js` خادمٌ ثابت بلا تبعيّات يخدم `dist/` برؤوس تخزين مضبوطة — وهو ما
يشغّله Railway على `f6een.com`. والبناء ينظّف بعده نسخَ iCloud المكرّرة
(«اسم 2.jpg») من `dist/` كي لا تُشحن مضاعفةً في التطبيق.

### التطبيق الأصليّ (آيفون وآيباد وأندرويد)

```bash
npm run ios       # يبني ويزامن ويفتح Xcode
npm run android   # يبني ويزامن ويفتح Android Studio
```

الاتجاه مقفول أفقياً من النظام في الاثنين، والدخول بغوغل داخل التطبيق
بلا متصفّح (`signInWithIdToken`). التفاصيل في `src/lib/auth.ts`.

## وضع الاختبار السريع

أضِف `?fast` للرابط لتقليص كل المؤقتات إلى العُشر — للتنقّل السريع بين الشاشات أثناء التجربة، لا للّعب:

```
http://localhost:4173/?fast
```

## الاختبارات

```bash
npm test
```

تحرس ضمانتين لا يكشفهما التصفّح اليدوي — لا سؤال يظهر مرّتين في الجلسة،
ولا قالبان من عائلة واحدة — وتقود جلسةً كاملة عبر المحرّك نفسه
(`session-flow.test.ts`). تُشغَّل قبل أي commit يمسّ `src/game/`.

## ما هو مبنيّ

| الشاشة | الحالة |
|---|---|
| التعريف والدخول (غوغل والبريد) | ✅ |
| الإعداد: الفرق واللاعبون وفئات اللوح والقرعة | ✅ |
| ١ لوح الجولة الجماعية (ستّ فئات × ثلاثة مستويات) | ✅ |
| ٢ سؤال الجولة الجماعية | ✅ |
| ٣ كشف وتنقيط الجولة الجماعية | ✅ |
| ٤ اختيار لاعبَي الديربي | ✅ |
| ٥ كشف وتنقيط الديربي | ✅ |
| ٦ الحق ما تلحق | ✅ |
| ٧ الفاصل | ✅ |
| ٨ الختام والتبليغ عن سؤال | ✅ |
| فاصل التعادل | ✅ |
| حسابي: الرصيد وكود الهدية وسجلّ الألعاب وحذف الحساب | ✅ |
| لوحة الإدارة (`/admin.html`) | ✅ |

**غير مبنيّ:** الدفع — الأسعار معروضة والزرّ موقوف حتى يُحسم المسار (SPEC ١٣).

## البنية

```
src/
  game/        منطق اللعبة الخالص (بلا واجهة)
    types.ts     الأنواع
    bank.ts      قراءة بنك الأسئلة وفهرسته، وطبقة اللوحة فوقه
    draw.ts      خوارزمية السحب (القسم ٨ من SPEC)
    session.ts   الثوابت وإنشاء الجلسة والذاكرة وفحص اللقطة
    reducer.ts   كل انتقالات الحالة
  components/  عناصر مشتركة (المؤقت، شريط النتيجة، الصورة…)
  screens/     شاشة لكل مرحلة
  lib/         الحساب والقاعدة (supabase, auth, games, admin)
  admin/       لوحة الإدارة — صفحة مستقلّة، لا تُحمَّل مع اللعبة
  skins/       الهويّتان «نيو» و«البلوكات» فوق theme.css
data/          بنك الأسئلة — للقراءة فقط
assets/        الشعار والأيقونة وصور الفئات — معتمدة نهائياً
supabase/      مخطّط القاعدة وهجراتها
server.js      خادم النسخة المنشورة
ios/ android/  مشروعا Capacitor
```

## لوحة الإدارة

`/admin.html` — صفحة ثانية في نفس البناء: الحسابات وأرصدتها، الجلسات،
أكواد الهدية، بلاغات الأسئلة وحجزها، وكل الأسئلة بتعديلها وإضافتها ورفعها
من ملفّ. صلاحيتها صفٌّ في جدول `admins` داخل القاعدة لا شرطٌ في الواجهة،
والتفاصيل في [`supabase/README.md`](supabase/README.md).

## قرارات معمارية مثبّتة

- **سحب مسبق لكل أسئلة الجلسة عند إنشائها** — ٤٠ سؤالاً احتياطاً للحق ما تلحق
  (ويُمدَّد الطابور إن نفد)، والباقي عند كل خليّة. الجلسة تعمل كاملة بلا
  إنترنت لأن واي فاي المجلس غير موثوق.
- **الحفظ المحلي مستمر** — أي انقطاع أو إغلاق يرجع لنفس الجلسة بنفس النقاط
  والأسئلة، ضمن نافذة ٢٤ ساعة؛ وفوقه لقطةٌ على الخادم للاستئناف من جهاز آخر.
- **`used_question_ids` محفوظة محلياً** في `localStorage` وتُزامَن مع الخادم
  عند توفّر الحساب — الاتّجاهين معاً.
- **البنك ملفٌّ يُشحن مع التطبيق** والقاعدة تحمل الفرق وحده (ما عُدّل وأُضيف
  من اللوحة).
